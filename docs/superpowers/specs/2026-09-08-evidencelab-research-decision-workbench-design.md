# EvidenceLab 科研决策工作台设计

## 1. 背景与目标

MindBridge 当前是校园心理健康智能体，已经具备受控多 Agent loop、混合 RAG、短期与长期记忆、SSE 流式输出、运行轨迹、结构化报告和后台工具链。

本次改造将产品完整转换为面向个人计算机与 AI 研究者的科研决策工作台 EvidenceLab。系统不以论文问答或自动写综述为核心，而是帮助研究者基于论文、项目资料、实验日志和历史决策回答以下问题：

- 当前约束下应该选择哪个模型、数据集、训练策略或评测方案；
- 论文结论是否适用于当前任务、算力和数据规模；
- 一次实验失败后，下一组最值得执行的验证实验是什么；
- 某项建议由哪些证据支持、有哪些反对证据、还缺少什么信息；
- 历史决策最终是否得到实验结果支持，以及能够沉淀什么经验。

产品的核心闭环是：

```text
研究问题 → 证据检索 → 证据审查 → 决策草稿 → 用户确认
→ 实验验证 → 结果复盘 → 研究记忆
```

## 2. 产品原则

### 2.1 决策优先

项目、资料、实验和决策是一级业务对象。对话只是发起问答或分析的入口，不能继续作为产品首页的唯一中心。

### 2.2 证据可追溯

决策中的重要结论必须能够回到具体来源位置，包括论文页码与章节、Markdown 标题、README 段落或实验日志行号。无法定位来源的内容不能作为已验证事实展示。

### 2.3 不确定性显式化

系统必须同时展示支持证据、反对证据、适用条件差异和证据缺口。证据不足时可以给出待验证建议，但不能包装为高置信度结论。

### 2.4 人在决策回路中

模型生成的内容默认是草稿。只有用户明确确认后，决策才能进入正式账本；系统不能替用户自动确认研究决策。

### 2.5 受控多 Agent

Agent 执行顺序和最大步数由代码控制，模型只完成边界明确的专业判断。第一版不允许模型任意创建 Agent、自由选择工具或无限循环。

## 3. 第一版范围

### 3.1 包含

1. 创建个人研究项目，维护研究目标和约束。
2. 上传 PDF、Markdown 和 TXT 资料，并建立项目级检索索引。
3. 记录 AI/计算机实验的假设、配置、指标、日志和结论。
4. 对资料进行带来源定位的普通问答。
5. 针对研究问题运行多 Agent 决策流程并生成结构化决策卡。
6. 用户确认决策、关联验证实验并回填实验结果。
7. 对预期与实际结果进行复盘，形成可检索的研究记忆。
8. 查看每次多 Agent 运行的步骤、检索 query、耗时和降级信息。

### 3.2 不包含

- 联网自动搜索或下载论文；
- 自动执行训练代码或操作 GPU 环境；
- 自动撰写完整论文或文献综述；
- 多人协作、权限审批和组织空间；
- GraphRAG 或知识图谱数据库；
- 无需用户确认的全自动科研决策。

这些能力只有在第一版闭环经过真实使用验证后再评估。

## 4. 信息架构与界面

### 4.1 全局页面

- 项目列表：创建、搜索和进入研究项目；
- 账号设置：个人资料、模型与检索配置。

### 4.2 项目工作区

项目工作区采用“决策优先”布局，包含五个一级页面：

- 项目概览：研究目标、约束、当前活跃决策、证据缺口和待回填实验；
- 决策账本：决策列表、版本、状态、置信度和最终复盘结论；
- 实验记录：实验假设、配置、指标、日志和结果；
- 证据库：资料列表、解析状态、来源元数据和检索预览；
- Agent 轨迹：路由、检索、审查、决策和降级过程。

研究助手以右侧抽屉存在。普通问答不会自动生成正式决策；用户点击“生成决策”后才进入完整的证据审查与决策链路。

### 4.3 项目首页默认内容

项目首页优先展示一项活跃决策，包括：

- 当前研究问题；
- 当前建议与置信度；
- 支持和反对证据数量；
- 尚未解决的证据缺口；
- 下一步最小验证实验；
- 关联实验的回填状态。

没有活跃决策时，页面展示项目目标、约束摘要，并引导用户从资料、实验记录或新研究问题开始。

## 5. 多 Agent 架构

### 5.1 执行顺序

```text
ResearchContextAgent
→ SupervisorAgent
→ EvidenceAgent
→ EvidenceCriticAgent
→ ResearchAssistantAgent / DecisionAgent
```

Agent 根据共享上下文状态判断是否执行。代码按照固定优先级选择下一个 Agent，整个 loop 继续保留最大步数限制。

### 5.2 Agent 职责

#### ResearchContextAgent

加载当前项目目标、约束、最近实验、历史决策、对话窗口和相关长期研究记忆。它只准备上下文，不检索外部知识，也不提出建议。

#### SupervisorAgent

将每次输入路由为以下一种意图：

- `GENERAL_CHAT`：不依赖项目资料的普通技术问题；
- `EVIDENCE_QUERY`：针对论文、项目文档或实验事实的查询；
- `RESEARCH_DECISION`：方案比较、失败诊断或下一步实验决策；
- `RESULT_REVIEW`：基于已回填实验结果复盘历史决策。

#### EvidenceAgent

在当前项目内执行混合检索。它可以结合项目约束改写 query，在证据不足时进行一次二次检索。单次 Agent run 最多执行两次检索，防止无界扩张。

#### EvidenceCriticAgent

检查检索证据是否真正支持候选结论，识别不同来源的冲突、实验条件差异、缺失 baseline、指标不可比和未验证假设。它输出结构化审查结果，不生成最终建议。

#### ResearchAssistantAgent

处理 `GENERAL_CHAT` 和 `EVIDENCE_QUERY`。资料问答需要显示来源，普通技术问答不强制检索项目资料，也不生成决策记录。

#### DecisionAgent

处理 `RESEARCH_DECISION` 与 `RESULT_REVIEW`：

- 决策模式输出候选方案、权衡、证据、反证、不确定性、推荐方案和最小验证实验；
- 复盘模式比较原始预期与实际结果，生成支持程度、偏差原因和可复用经验。

实验状态更新、提醒和确定性数据写入由普通业务服务负责，不创建缺少独立认知职责的 TrackerAgent。

### 5.3 路由路径

```text
GENERAL_CHAT
Context → Supervisor → ResearchAssistant

EVIDENCE_QUERY
Context → Supervisor → Evidence → ResearchAssistant

RESEARCH_DECISION
Context → Supervisor → Evidence → Critic → Decision

RESULT_REVIEW
Context → Supervisor → Evidence → Critic → Decision
```

## 6. 领域模型

### 6.1 ResearchProject

表示一个独立研究项目，至少包含：

- 所有者；
- 名称与描述；
- 研究目标；
- 任务类型；
- 算力、时间、数据和指标约束；
- 项目状态与创建、更新时间。

所有资料、切片、实验、决策、会话和 Agent 轨迹必须关联项目。

### 6.2 ResearchSource

表示进入证据库的原始资料。来源类型固定为：

- `PAPER`；
- `NOTE`；
- `REPOSITORY_DOCUMENT`；
- `EXPERIMENT_LOG`。

记录原始文件名、内容类型、解析状态、失败原因、上传时间和来源元数据。解析状态区分等待、处理中、可检索和失败。

### 6.3 KnowledgeChunk

在现有知识片段基础上增加：

- 项目标识和来源标识；
- 页码；
- 章节标题；
- 起止位置；
- 来源类型；
- 原始片段文本和检索文本。

不同格式只填写能够可靠获得的位置字段，不能伪造页码或行号。

### 6.4 ExperimentRun

记录：

- 实验名称、研究假设与状态；
- 关联项目和可选关联决策；
- 模型、数据集和关键配置；
- 随机种子、环境摘要和代码版本；
- 指标与日志；
- 用户编写的结果结论；
- 开始、结束和回填时间。

第一版由用户手动录入或上传实验日志，不自动运行训练任务。

### 6.5 DecisionRecord

记录：

- 研究问题；
- 候选方案；
- 当前推荐及理由；
- 置信度；
- 证据缺口；
- 最小验证实验与成功标准；
- 状态、版本和生成该版本的 Agent trace；
- 用户确认时间。

决策状态固定为：

```text
DRAFT → CONFIRMED → VALIDATING → REVIEWED
```

已确认决策不能被静默覆盖。新的模型分析生成新版本，并保留旧版本用于比较。

### 6.6 DecisionEvidence

关联决策版本与知识片段，保存：

- 立场：`SUPPORT` 或 `OPPOSE`；
- 该片段支持或反对的具体 claim；
- 相关性和适用性说明；
- 引用展示位置。

### 6.7 DecisionReview

关联一个决策版本和至少一个实验记录，保存复盘结论：

- `SUPPORTED`；
- `PARTIALLY_SUPPORTED`；
- `REFUTED`；
- `INCONCLUSIVE`。

同时保存预期与实际差异、可能原因、经验和后续建议。

### 6.8 AgentRunTrace

复用现有运行轨迹能力，增加项目、可选决策版本、执行耗时、检索降级状态和结构化失败原因。轨迹用于调试与审计，不向用户暴露模型隐式推理过程。

## 7. RAG 设计

### 7.1 项目隔离

所有向量检索、本地检索、相邻片段扩展和 rerank 都必须先按项目过滤。任何跨项目召回都视为严重缺陷。

### 7.2 检索流程

```text
项目过滤
→ query 改写
→ 向量检索与 BM25
→ 候选合并
→ rerank
→ 相邻片段扩展
→ 证据充分性检查
→ 必要时一次精炼检索
```

不同来源类型可以参与同一次检索，但结果必须保留类型，使后续 Agent 能区分论文结论、项目文档、实验事实和历史决策。

### 7.3 引用与事实边界

- 每条决策证据必须关联真实 `KnowledgeChunk`；
- 生成结果只能引用本次 Agent run 实际检索到的片段；
- 引用文本和来源位置由服务端根据关联片段组装，不能完全信任模型自由生成；
- 无法验证的模型输出降级为“推测”或删除；
- 论文证据与个人实验结果在界面上使用不同标识。

### 7.4 第一版不使用 GraphRAG

当前混合检索已经具备向量、BM25、rerank 和相邻片段扩展。第一版优先完成项目隔离、来源定位、证据绑定和可量化评测。只有真实使用证明跨文档关系推理是主要瓶颈时，再评估 GraphRAG。

## 8. 结构化输出

Supervisor、EvidenceCritic 和 Decision Agent 的模型结果必须通过字段明确的数据结构解析与校验。

决策草稿至少包含：

- 问题重述；
- 候选方案列表；
- 推荐方案；
- 支持证据引用；
- 反对证据引用；
- 适用条件；
- 证据缺口；
- 置信度；
- 最小验证实验；
- 成功标准。

模型返回无法解析时，系统使用固定修复提示重试一次。第二次仍失败则终止本次决策生成，不保存半结构化记录。

## 9. 数据流

### 9.1 资料摄取

```text
上传文件
→ 校验项目归属、类型和大小
→ 创建 ResearchSource
→ 解析文本与位置元数据
→ 切块
→ 生成 embedding
→ 保存关系库和向量索引
→ 标记为可检索
```

解析或 embedding 失败必须保存明确状态，使用户能够重新处理。

### 9.2 生成决策

```text
提交研究问题
→ 创建 Agent run
→ 加载项目上下文
→ 路由
→ 项目级检索
→ 证据审查
→ 生成并校验决策草稿
→ SSE 返回阶段进度和结果
→ 用户确认
→ 保存正式决策版本
```

SSE 对外展示 Agent 名称、阶段状态和结果摘要，不展示隐式思维链。

### 9.3 实验复盘

```text
用户回填实验
→ 关联历史决策
→ 加载原始预期、证据和实际结果
→ 执行 RESULT_REVIEW
→ 生成结构化复盘草稿
→ 用户确认
→ 更新决策状态并写入研究记忆
```

## 10. 错误处理与降级

- PDF 解析失败：保留来源记录与失败原因，不进入可检索状态；
- embedding 失败：降级为 BM25，Agent run 和决策草稿明确记录检索降级；
- RAG 无结果：资料问答说明未找到项目证据，决策只能生成低置信度待验证建议；
- 结构化输出失败：固定重试一次，仍失败则终止，不保存正式业务记录；
- 引用无法绑定：删除对应事实性结论或标记为未验证推测；
- Agent 超时或超过步数：终止运行并保存已完成轨迹；
- 实验结果不完整：允许保存实验草稿，但不执行决策复盘；
- 单个 Agent 失败：只有不影响事实可靠性的环节可以降级，EvidenceCritic 或 Decision 失败时不得生成正式决策；
- 重复提交：确认决策和回填结果需要幂等控制，避免产生重复版本。

## 11. 安全与数据边界

- 所有项目资源按所有者和项目双重校验；
- 下载、预览、检索和 Agent 调用不能通过资源 ID 绕过项目权限；
- 上传文件限制类型、大小和解析时间；
- 日志不记录完整论文、用户密钥或大段模型上下文；
- 模型提供商配置与用户资料分离；
- 删除项目时必须明确列出将删除的资料、索引、实验、决策和会话，执行前再次确认。

第一版是个人产品，但数据模型和访问控制仍按多用户隔离设计，避免后续公开部署时重写边界。

## 12. 测试与评测

### 12.1 单元与集成测试

- 四类意图路由；
- 各 Agent 的 `supports` 状态转换和最大步数；
- 决策状态机与版本保留；
- 项目级 Repository 查询和权限过滤；
- 文件解析状态流转；
- 结构化模型输出的正常、修复和失败路径；
- embedding 降级至 BM25；
- 引用与知识片段绑定；
- SSE 阶段事件和错误事件；
- 确认决策与结果回填的幂等性。

### 12.2 RAG 与 Agent 评测

复用现有评测 harness，建立 AI/计算机研究场景数据集，至少度量：

- 意图路由准确率；
- Retrieval Recall@K；
- 引用准确率和 claim-source 支持率；
- 支持与反对立场判断准确率；
- 冲突证据发现率；
- 决策结构化输出成功率；
- 项目隔离泄漏率；
- 决策到实验再到复盘的端到端状态正确率。

第一版验收阈值如下：

- 意图路由准确率不低于 90%；
- Retrieval Recall@5 不低于 85%；
- 引用准确率和 claim-source 支持率不低于 95%；
- 支持与反对立场判断准确率不低于 85%；
- 冲突证据发现率不低于 80%；
- 决策结构化输出成功率不低于 98%；
- 项目隔离泄漏率必须为零；
- 标注端到端闭环用例必须全部通过。

上述阈值使用版本化评测集计算；评测集修改后需要保存版本号，避免通过更换样例掩盖回归。

### 12.3 真实演示场景

第一版使用一个贯穿式示例进行验收：

> 在 12 GB 显存、7B 模型和中文分类任务下，应该选择 LoRA 还是 QLoRA？

演示资料包含相关论文、项目 README、一次 OOM 日志和若干历史实验。完整演示必须覆盖上传、检索、证据冲突、决策确认、实验回填和结果复盘。

## 13. 现有模块迁移

| 当前模块 | EvidenceLab 职责 |
| --- | --- |
| MemoryAgent | ResearchContextAgent |
| SupervisorAgent | 四类科研意图路由 |
| KnowledgeAgent | EvidenceAgent |
| RiskGuardianAgent | EvidenceCriticAgent |
| CompanionAgent | ResearchAssistantAgent |
| CounselorAgent | DecisionAgent |
| PsychologicalReport | DecisionRecord 与 DecisionReview |
| RiskLevel | 决策置信度和证据充分性 |
| AlertRecord | 运行失败、证据缺口和待复盘提醒 |
| 用户画像记忆 | 项目研究记忆 |
| Excel 报告 | 决策账本与实验记录导出 |
| AgentRunTrace | 项目级 Agent 运行轨迹 |

改造采用完整领域替换，不长期保留心理健康与科研决策两套模型并行。现有心理健康演示数据不迁移到新领域表；开发环境首次切换时重新初始化 EvidenceLab 示例数据。生产代码中不保留心理语义兼容分支。

## 14. 实施边界与验收标准

完成第一版后，用户应能够：

1. 创建研究项目并填写目标与约束；
2. 上传至少三种支持格式的项目资料；
3. 针对项目资料进行带来源定位的问答；
4. 发起一次研究决策并看到多 Agent 阶段进度；
5. 获得包含支持证据、反对证据、缺口和验证实验的决策草稿；
6. 确认草稿并在账本中保留不可静默覆盖的版本；
7. 创建并回填关联实验；
8. 生成复盘并将决策推进到 `REVIEWED`；
9. 查看完整 Agent 运行轨迹；
10. 通过自动化测试证明项目资料不会跨项目召回。
